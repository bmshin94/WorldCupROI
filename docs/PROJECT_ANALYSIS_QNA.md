## 1. 이 프로젝트는 뭐 하는 건가

**WorldCupROI = "AI 스포츠 스폰서십 ROI 의사결정 플랫폼"** 포트폴리오 프로젝트입니다.

일반적인 축구 분석 프로젝트가 "누가 이길까?"에서 멈추는 데 비해, 이 프로젝트는 한 단계 더 나아가
**"어떤 브랜드가 어떤 팀을 어떤 전략으로 후원하면 투자 수익(ROI)이 가장 좋을까, 그리고 그 리스크는 얼마인가?"**
를 답하도록 설계되어 있습니다.

핵심 워크플로우:

```text
Discover(탐색) -> Explain(설명) -> Predict(예측) -> Simulate(시뮬레이션) -> Recommend(추천)
```

### 4계층 알고리즘 구조

1. **경기 결과 레이어** — Centroid 분류기 (정확도 0.5566, 로그로스 0.9780)
2. **스폰서 ROI 레이어** — Ridge 회귀 (MAE 0.1177, R² 0.8838)
3. **리스크/추천 레이어** — Bootstrap, Monte Carlo, Conformal 예측구간, 시나리오 랭킹
4. **관계 지능 레이어** — NetworkX 중심성 + GraphSAGE 스타일 이웃 집계 점수

### ⚠️ 가장 중요한 발견 (정직한 평가)

`src/feature_builder.py:77-98`에서 **정답값인 `sponsor_roi` 자체를 수식으로 직접 만들어냅니다.**

```python
df["sponsor_roi"] = (0.75
    + 1.15 * df["fan_score"]
    + 0.90 * df["a_sponsor_power_index"]
    + 0.55 * df["team_a_strength"]
    + exposure_efficiency + ad_efficiency + player_availability
    + stage_weight + result_boost
    - 0.035 * df["a_sponsor_spend_m"]
    + rng.normal(0, 0.12, len(df)))
```

그리고 `ml_config.py`의 `ROI_FEATURES`에는 `fan_score`, `a_sponsor_power_index`,
`team_a_strength` 등 **그 수식의 재료가 그대로** 들어 있습니다.

즉 **R² 0.8838은 "모델이 자기가 만든 공식을 되찾은 점수"**입니다.
실제 광고비 대비 매출을 맞춘 성능이 아닙니다. (프로젝트 자체도 `reports/data_card.md`,
README의 "Trust level: Medium-low / proxy-mock" 표기로 이 경계를 명시하고 있어 은폐는 아닙니다.)

실제 데이터와 프록시 데이터 경계:

| 구분 | 내용 | 신뢰도 |
|---|---|---|
| **진짜 실제 데이터** | 국제경기 49,478행, GDELT 기사 메타데이터, Wikipedia 본문, 공식 스폰서 10개사 이름 | 중상 |
| **프록시(합성) 데이터** | 스폰서 집행액, 광고 노출량, 브랜드 열기지수, 활성화 품질, 전환율, **그리고 ROI 정답값** | 중하 |

| **대시보드 UX 설계 참고** | 차트 나열이 아니라 5페이지 의사결정 동선으로 설계된 구조 |
| **콘텐츠 소재** | README 자체가 완성된 기술 블로그/강의 대본 수준 |

### 바로 쓰면 안 되는 용도 ❌

- 실제 기업에 스폰서십 ROI 수치를 보고하는 용도 (ROI 정답값이 합성 데이터)
- "축구 승부 예측기"로 쓰는 용도 (정확도 0.5566 — 3클래스에서 거의 기준선 수준)
- 모델 성능 수치(R² 0.88)를 외부에 실력 지표로 제시하는 용도

### 내가 얻을 수 있는 실익 정리

1. **설계 역량의 증거** — 38개 모듈이 YAML 선언 + `importlib` 동적 로딩으로 느슨하게 결합된 구조는 중급 이상 설계입니다.
2. **문서화 자동화 패턴** — `src/project_docs.py`(27KB)가 데이터카드/모델카드/배포문서를 코드에서 자동 생성합니다. 실무에서 그대로 쓸 수 있는 패턴.
3. **의존성 없는 ML 구현체** — Ridge/Centroid를 NumPy로 직접 구현해 두었습니다. 면접에서 "직접 구현해봤냐"에 답할 재료.
4. **GIF 자동 캡처 파이프라인** — Playwright로 대시보드를 자동 촬영해 README에 넣는 흐름(`scripts/capture_*.js`)은 다른 모든 프로젝트에 재사용 가능.

## 3. 핵심 Q&A

### Q1. 설치 및 사용법?

**최소 요구사항:** Python 3.11, 디스크 여유 ~500MB (레포 167MB + 패키지)

```bash
git clone https://github.com/bmshin94/WorldCupROI.git
cd WorldCupROI
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python src/pipeline.py --demo      # 전체 파이프라인 (오프라인, 네트워크 불필요)
streamlit run dashboard/app.py -- --demo   # http://localhost:8501
```

**실행 모드 3종**

| 명령 | 동작 |
|---|---|
| `python src/pipeline.py --demo` | 완전 오프라인. `preprocess.py`로 로컬 합성 데이터 생성 후 전체 실행. **추천 (처음 실행 시)** |
| `python src/pipeline.py` | `real_data_ingestion.py`로 GDELT + Wikimedia + GitHub CSV를 실시간 수집 |
| `python src/pipeline.py --skip-ingestion` | 커밋된 데이터 재사용. CI에서 쓰는 모드 |

**더 빠른 확인 방법 (설치 0분)**

```bash
# 파이썬 없이도 바로 열림 — 이미 생성된 정적 대시보드
open dashboard/panel_dashboard.html   # Windows: start, Linux: xdg-open
```

**Docker**

```bash
docker build -t worldcuproi .
docker run --rm -p 8501:8501 worldcuproi
```

**주의:** `make pipeline`은 Makefile의 윈도우 절대경로 때문에 실패합니다.
`make PYTHON=python3 pipeline` 으로 우회하거나 Makefile 1행을 수정하세요.

### Q4. AI 에이전트를 구축하는 데 도움이 될까?

**도움 됩니다. 단, "에이전트 프레임워크"가 아니라 "에이전트가 호출할 도구 묶음"으로서요.**

중요한 구분: 이 프로젝트에는 **LLM 호출 코드가 0줄**입니다.
`src/generative_insight_engine.py`, `src/generative_report.py`의 "generative"는
LLM이 아니라 **템플릿 문장 조립**입니다.

| 측면 | 평가 |
|---|---|
| 에이전트 **프레임워크** 학습 | ❌ 플래너/메모리/툴루프 없음 |
| 에이전트가 쓸 **툴 공급원** | ⭐⭐⭐⭐⭐ 38개 모듈이 각각 명확한 입출력을 가진 함수 |
| 에이전트 **아키텍처 패턴** 참고 | ⭐⭐⭐⭐ YAML 선언 + `importlib` 동적 로딩 = 툴 레지스트리와 동일 패턴 |
| **구조화 출력** 설계 참고 | ⭐⭐⭐⭐ `reports/algorithm_manifest.json`, `platform_health.json` |

**가장 현실적인 업그레이드 (실제로 추천하는 작업)**

`src/pipeline.py`의 `PipelineStep` + `load_main()` 구조는 **이미 툴 레지스트리와 똑같습니다.**
이걸 MCP 서버로 감싸면 3단계 만에 에이전트 도구가 됩니다:

```python
# 1. 각 모듈 main()을 MCP tool로 노출
@mcp.tool()
def rank_sponsor_scenarios(team: str, budget_m: float) -> dict:
    """팀과 예산을 받아 보수/균형/공격 전략 랭킹을 반환"""
    from scenario_engine import rank_scenarios
    return rank_scenarios(team=team, budget=budget_m)

# 2. 리포트 생성부를 LLM 호출로 교체
#    generative_insight_engine.py의 템플릿 → Claude API 호출
# 3. ROI 수치 + 리스크 + 그래프 근거를 컨텍스트로 넘겨 브리프 작성
```

이렇게 하면 **"스폰서십 애널리스트 에이전트"**가 됩니다. 사용자가 자연어로
"브라질에 2천만 달러 쓰면 어때?" 물으면 → 에이전트가 ROI 모듈 호출 → 리스크 계산 →
근거 있는 브리프 생성. 데이터와 계산 로직이 이미 다 있으니 LLM 레이어만 얹는 작업입니다.

### Q6. 우리가 React나 PHP로 만들 수 있어?

**가능합니다. 단, 분업 전략을 추천합니다.**

| 레이어 | 언어 선택 | 이유 |
|---|---|---|
| 프론트엔드 | **React** ⭐ | 현재 대시보드는 Plotly.js를 쓰므로 `react-plotly.js`로 거의 1:1 포팅 |
| API 서버 | **FastAPI(Python)** ⭐ | 모델/통계 로직이 이미 Python. 재작성 불필요 |
| 혹은 API | PHP (Laravel) | 가능하지만 Ridge/Monte Carlo/Conformal을 PHP로 재구현해야 함 → 비추천 |
| 배치 작업 | Python 유지 | 파이프라인 그대로 cron/Celery로 |

**React 포팅 난이도 분석**

| 항목 | 난이도 | 비고 |
|---|---|---|
| Plotly 차트 10여 종 | 🟢 쉬움 | `assets/vendor/plotly.min.js` 이미 사용 중 → `react-plotly.js` |
| 필터/드롭다운 (팀/스폰서/스테이지/연도) | 🟢 쉬움 | 일반 `useState` |
| 5페이지 라우팅 | 🟢 쉬움 | React Router |
| 다국어 (영어/중국어 이미 구현됨) | 🟢 쉬움 | `dashboard/app.py`의 `I18N` dict를 그대로 i18next로 |
| CSV/PDF 내보내기 | 🟡 보통 | 서버 사이드 엔드포인트 필요 |
| Monte Carlo / Conformal 계산 | 🔴 어려움 | **JS 재구현 비추천 → API로 넘길 것** |
| 그래프 네트워크 시각화 | 🟡 보통 | `react-force-graph` 또는 Cytoscape.js |

**추천 아키텍처**

```text
[React + Vite + TailwindCSS]  ← 대시보드 UI, Plotly 차트
            ↕ REST / JSON
[FastAPI]                     ← /api/roi, /api/scenarios, /api/graph, /api/risk
            ↕
[기존 src/ 38개 모듈 그대로]   ← 계산은 손 안 댐
            ↕
[PostgreSQL]                  ← sql/schema.sql 확장
```

**PHP를 꼭 써야 하는 경우:** 기존 PHP 서비스에 붙이는 상황이라면,
PHP는 **인증/결제/회원관리만** 담당하고 분석 요청은 Python FastAPI로 프록시하세요.
통계 로직을 PHP로 옮기는 건 손해입니다.

**예상 공수:** React + FastAPI 포팅 — 혼자서 약 3~4주 (MVP 기준 2주)

### Q7. 유튜브 강의 영상으로 제작 가능할까?

**매우 적합합니다. 교보재로 거의 완벽합니다.** 🎬

**왜 적합한가**

| 강점 | 설명 |

> ⚠️ **전제 조건:** 합성 ROI 데이터를 **반드시** 실제 캠페인 데이터로 교체해야 합니다.
